# 커밋 가이드

커밋 메시지는 영문 접두와 한글 본문으로 쓴다. 영문은 종류를 가리키는 접두만 쓴다.

```
feat : 각 문서 페이지 수정 및 커밋 가이드 작성
```

접두와 본문 사이에는 공백, 콜론, 공백을 둔다.

## 접두

| 접두 | 쓸 때 |
|---|---|
| `feat` | 기능이나 문서 구조를 새로 만들 때 |
| `fix` | 잘못된 동작을 고칠 때 |
| `docs` | 기존 문서의 내용만 고칠 때 |
| `refactor` | 동작은 유지하고 구조를 정리할 때 |
| `test` | 테스트나 테스트 기록을 추가할 때 |
| `chore` | 기능과 무관한 정리일 때 |

본문에는 영문 문장을 섞지 않는다. 파일 이름, 폴더 이름, 브랜치 이름, 명령어처럼 고유한 표기는 그대로 둔다.

## 남기는 곳

커밋 전에 `records` 폴더에 기록을 만든다. 형식은 `COMMIT_TEMPLATE.md`를 따른다. 파일 이름은 일련번호 네 자리다. 예: `0001.md`.

기록에는 일련번호, 날짜와 시간(초까지), 커밋 작업 내용, 상세 내용, 결과를 적는다. 결과에는 브랜치와 해시를 적는다. 해시는 커밋이 끝난 뒤 `git log -1 --format=%H`로 확인해 기록에 넣는다.

게임 원본 변경 지시가 없는 커밋에서는 원본 파일을 스테이징하더라도 내용 변경이 없어야 한다. 변경이 있으면 커밋하지 않고 이유를 기록한다.

## 담당과 파트

커밋은 담당 브랜치에 나눈다. 클라이언트 변경은 `Client`, 서버 변경은 `Server`, 데이터베이스 변경은 `database`에 둔다. `Devolop`은 병합과 테스트용이라 기능 커밋을 직접 넣지 않는다. `master`는 메인과 배포용이다.

같은 브랜치에서도 작업 파트마다 커밋을 나눈다. 화면, 소환, 합성, 배속처럼 고친 이유가 다르면 한 커밋에 섞지 않는다.

## 확인

커밋 뒤 아래를 대조한다.

1. `Docs/Branchs/commits/records`의 최신 기록
2. `git log -1 --format=%H%n%s`
3. `git status`에 남긴 의도치 않은 변경
